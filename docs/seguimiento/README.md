## Cómo completar cada revisión

1. Antes de la reunión, abrid el archivo correspondiente y reunid los enlaces a issues, pull requests, cambios y documentos que se van a revisar. Cuando exista, añadid el enlace al GitHub Project.
2. Durante la reunión, Rocío y Pablo completáis conjuntamente los apartados **1–7**: asistentes, alcance, trabajo realizado, riesgos, retrospectiva, plan y acuerdos. Cambiad las opciones de ejemplo por el estado real y marcad una casilla solo cuando se haya realizado.
3. Cada integrante completa su propia fila del **apartado 8**: aportación concreta, evidencia, decisión o problema que puede explicar y siguiente paso. Una tarea compartida puede aparecer en ambas filas si cada persona explica su contribución.
4. Enlazad los resultados y actualizad el tablero cuando esté disponible. Si no hubo incidencias, escribid «No se han identificado». Si alguien no asistió, indicad cómo recibirá los acuerdos.
5. En la revisión final, usad el apartado de siguiente ciclo para recoger acciones posteriores acordadas; si no hay ninguna, indicadlo. No es necesario inventar un sprint adicional.

La primera revisión ya contiene enlaces al alcance y a los documentos que existen en el repositorio. Completad la asistencia, los estados de entrega, las decisiones, la retrospectiva y las aportaciones individuales según lo ocurrido.

## Criterios para las evidencias

Enlazad un recurso que permita comprobar cada avance: el issue que describe el trabajo, la pull request revisada, el commit, el documento modificado o una prueba verificable. Indicad qué se comprobó y su resultado; un enlace o una asignación por sí solos no demuestran que una tarea esté terminada. Evitad incluir datos personales de residentes, contraseñas o claves en el repositorio público.
